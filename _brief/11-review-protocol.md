بروتوكول المراجعة

> **مبدأ:** اللى كتب المادة مايراجعهاش. المراجع بيقرا الملفات من الصفر وبيفحص الشرائح بصريا.
> جرب على `16` جلسة فى `A1` وطلع `50+` مشكلة حقيقية.

---

## 1. الدورة

```
كتابة الجلسة → validate.mjs → مراجع مستقل يكتب تقرير → إصلاح بسكربت → validate.mjs → تسليم
```

المراجع **ما يعدلش أى ملف منهج** — بيكتب تقرير بس. الفصل ده مهم: بيمنع الإصلاح المتسرع وبيخلى القرار عند اللى شايف الصورة الكاملة.

---

## 2. برومبت المراجع — انسخه وغير اسم الجلسة

```
أنت مراجع تربوى وتقنى لمنهج برمجة للأطفال (أكاديمية 4U — مصر). راجع محاضرة واحدة واكتب تقرير.

المحاضرة: المستوى `A2` — الجلسة `S05`.
مجلد العمل: D:\03_Work\04_4U\docs\curriculum\

الخطوات:
1. اقرأ `_review/README.md` — محاور الفحص وشكل التقرير. التزم به حرفيا.
2. اقرأ المرجعية: `_shared/session-blocks.md` · `_shared/slide-system.md` · `_shared/pedagogy.md` ·
   `<track>/<level>/level.md` + أى بنك تخص الجلسة.
3. اقرأ ملفات المحاضرة التلاتة كاملة.
4. صور الشرائح ثم افتح **كل** صورة وافحصها بصريا:
   node _tools/render-deck.mjs <deck> _review/.render/<id>
5. تحقق من المعرفات فى بنوك `_shared/` ومن وجود الصور فى `assets/`.
   اطبع سكربتات ملفات المشروع وقارنها بالمواد حرفيا:
   node _tools/dump-sb3.mjs <ملفات المشروع>
6. اكتب التقرير فى `_review/<id>.md` بالشكل المحدد فى `README.md`.

قواعد صارمة:
- **ممنوع تعديل أى ملف** غير التقرير.
- عربى مصرى واضح، بلا تشكيل، المصطلحات الإنجليزية بين backticks.
- كل نقطة محددة: الملف · المكان · المشكلة · الإصلاح المقترح.
- ركز على: دليل المدرس بلا رغى لكن وافى · أكتر من مثال أو طريقة لكل مفهوم
  (بسيط 2 · متوسط 3 · صعب 4+) · الخطوات واعية بتجربة الطفل ·
  مطابقة المواد لملفات المشروع الفعلية.
- كل الشغل محلى. لا ترسل أى شىء لأى خدمة خارجية.

فى النهاية رد بملخص 5 أسطر: عدد النقاط الحرجة/المهمة/التحسين وأهم مشكلة واحدة.
```

---

## 3. شكل التقرير

```markdown
# مراجعة <id> — <عنوان الجلسة>

## الخلاصة
سطران أو تلاتة: الحالة العامة وأهم مشكلة.

## نقاط الإصلاح (مرتبة بالخطورة)
### حرج — يمنع تنفيذ الجلسة أو معلومة غلط
- [ ] `notes/S05.notes.md:41` — المشكلة بالتحديد — **الإصلاح المقترح:** ...
### مهم — يضعف الفهم أو التجربة
- [ ] ...
### تحسين
- [ ] ...

## عدد الأمثلة لكل مفهوم (من الملاحظات)
- المفهوم: `X` — `3` أمثلة — كافى / ناقص (المطلوب `n`)

## ما هو جيد ويجب الحفاظ عليه
- ...
```

**كل نقطة لازم تكون قابلة للتنفيذ:** الملف، المكان، المشكلة، الإصلاح. ممنوع «الشرائح تحتاج تحسين».

---

## 4. تصنيف الخطورة

| الفئة | المعيار |
| --- | --- |
| **حرج** | الجلسة هتفشل حية، أو معلومة تقنية غلط، أو الملف مش مطابق للمواد |
| **مهم** | الفهم هيضعف، أو المدرس هيتلخبط، أو الوقت مش هيكفى |
| **تحسين** | تحسين شكلى أو اتساق أو صياغة |

---

## 5. التوازى

- `5` مراجعين بالتوازى، كل واحد جلسة واحدة. أكتر من كده بيستهلك الحصة.
- كل مراجع بيكتب ملف مختلف — مفيش تعارض.
- لو المراجع اتوقف قبل ما يكتب، شغله بيضيع. **اللقطات بتفضل** فى `_review/.render/` فالإعادة أسرع.

---

## 6. الإصلاح

1. اقرا التقرير كله الأول — نقط كتير بتتقاطع.
2. **صنف:** إصلاح فى ملف الجلسة · إصلاح فى القالب (بينتشر للكل) · إصلاح فى ملف مشروع · إصلاح فى بنك مشترك.
3. اكتب `_review/.fix/fix-<id>.cjs` بالنمط المذكور فى `09-tools.md`.
4. لو الإصلاح فى القالب: عدل القالب ثم `sync-slides.mjs`.
5. لو فى ملف مشروع: عدل قاعدة التوليد ثم `make-checkpoints.mjs`.
6. `validate.mjs` ثم امسح التشكيل ثم أعد التصوير البصرى لو الشرائح اتغيرت.

---

## 7. نقط بترفضها بوعى

المراجع ممكن يقترح حاجة مش صح. أمثلة اتقبلت وواحدة اترفضت:

- **اتقبلت:** «الفاصل بيكرر نفس نشاط الافتتاح» — صح، اتغير.
- **اتقبلت:** «صورة التوقع بتكشف الإجابة» — صح، اتقسمت لصورتين.
- **اترفضت:** «حركة `bounce` على شريحة الفاصل قديمة الطراز» — دى شريحة فاصل لأطفال `10–12`، النطة مقصودة ومناسبة للسياق.

**القاعدة:** لو رفضت نقطة، اكتب ليه — عشان المراجع الجاى ما يعيدهاش.
